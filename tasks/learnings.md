# Learnings

Durable facts distilled from completed implementation runs. Read before starting work
in this repo; append only learnings that generalise beyond the task that surfaced them.

## CLI diagnostic tests must assert the distinguishing message text
- Type: recurring-finding
- Learning: `internal/cli/*_test.go` tests that assert only `err.Error()` contains the path, `":1:"`, a line number, or a count are vacuous — any unrelated line-1 diagnostic satisfies them. The established repo convention is to assert the tokens that identify *this* diagnostic (see `internal/cli/validate_test.go:253-258` asserting rule names plus symbol names, and `internal/parser/parser_test.go:53-80` asserting the message names both the declared and the supported version). New CLI leaves for a new error kind must assert the same distinguishing content as the parser-level test one layer down, not just position and count.
- Apply when: adding or reviewing a test in `internal/cli` (validate, fmt, export, diagram, schema) that exercises a new error or diagnostic path.

## Run repo tooling through `mise exec --`, not bare PATH
- Type: constraint
- Learning: `/Users/davidnguyen/Personal/Code/emod/mise.toml` pins `cargo:tree-sitter-cli = "0.26.9"`, but the user's global `~/.config/mise/config.toml` pins a separate `tree-sitter = "0.25.10"` that wins on PATH in a non-activated shell. The two CLIs emit different generated output (0.26.x drops the version suffix from the `parser.c` banner and rewrites `src/tree_sitter/array.h`; `grammar.json` and `node-types.json` are identical), so a bare `task test:grammar` can leave the tree looking clean while `mise exec -- task test:grammar` produces a ~111/72-line diff. CI (`jdx/mise-action@v4`) sees only the repo pin, so the repo-pinned resolution is the one that matters. CI has no dirty-tree gate, so this drift stays green and is only caught by checking `git diff --exit-code` yourself.
- Apply when: running any Taskfile target whose output is committed (notably `task test:grammar`), or verifying that generated files in a diff are reproducible.

## Generated tree-sitter `src/` stays gitignored
- Type: constraint
- Learning: `editors/tree-sitter-emod/.gitignore` ignores `src/` alongside `bindings/node/` and `node_modules/` — the repo does not track generated artefacts. A grammar change commits `grammar.js` and its corpus tests only. Do not un-ignore `src/` to satisfy a "regenerated output is committed" criterion: it would make every grammar change carry a ~3k-line diff whose bytes depend on which CLI generated it, and `task test:grammar` runs `tree-sitter generate` first so nothing depends on those files being tracked.
- Apply when: touching `editors/tree-sitter-emod/grammar.js`, or reviewing a diff that changes the grammar.

## A task criterion requiring "committed" output cannot close
- Type: constraint
- Learning: implement-flow commits a task only *after* it closes, so an acceptance criterion phrased as "... and the output is committed" is unsatisfiable from inside the task — the audit re-checks `git log`/`git ls-tree`, finds nothing, and reports the criterion unmet on every attempt until `maxResolve` is exhausted. This burned all 5 attempts on US-001 Task 4. Phrase the criterion against the working tree instead — "regenerating leaves the tracked files byte-identical", "the file exists and matches X". Note that "`git status` is clean" is *also* unusable: a task under review always has uncommitted work.
- Apply when: writing or reviewing acceptance criteria during decomposition, especially for tasks that produce generated or checked-in artefacts.

## New DSL keywords must stay usable as field names
- Type: pattern
- Learning: emod keywords are not reserved words — they remain valid identifiers inside `fields` blocks. The Go parser handles this with `Instance.checkIdentifierLike()` (`internal/parser/parser.go`), and the tree-sitter grammar mirrors it with a permissive `any_identifier: $ => /[a-zA-Z_][a-zA-Z0-9_]*/` plus a keyword token narrow enough to match only in its own position (e.g. `version_header` bakes the separator into the token via `token(seq('emod', /[ \t]+/))` with `token.immediate` digits, so a bare `emod` cannot pair with a number on the next line). Adding a keyword to `internal/lexer/token.go` therefore needs a corresponding "field named X" case on both sides — see `internal/parser/parser_test.go:224` "keywords are usable as field names" and `editors/tree-sitter-emod/test/corpus/version_header.txt::Field named emod inside a fields block`.
- Apply when: introducing a new keyword into the emod language, in the Go lexer/parser or the tree-sitter grammar.

## Formatter output always begins with `emod N`
- Type: convention
- Learning: `formatter.Format` unconditionally emits a version header as the first line (`emod %d` from `pinnedVersion`, preserving `Model.Version` when `VersionDeclared` is set, otherwise `ast.SupportedVersion`). Every expected string in `internal/formatter/formatter_test.go` and every canonical-output constant in `internal/cli/fmt_test.go` must start with that line, while *input* fixtures may omit the header (the parser implies version 1 and leaves `VersionDeclared` false). `fmt --check` fails a file whose only deviation is the missing header.
- Apply when: adding a formatter golden, a `RunFmt` fixture, or an `.emod` round-trip test.

## `docs/dsl-reference.md` anchors embed the section number
- Type: convention
- Learning: every heading in `docs/dsl-reference.md` is `## <n>. <Title>`, so its in-document links are number-prefixed slugs (`[Slice Patterns](#6-slice-patterns)`, `[Flows](#7-flows)`, `[Cross-References](#10-cross-references)`). Inserting, removing or reordering a section renumbers every heading below it *and* invalidates each link that cites one of those numbers — four such links exist today. Nothing catches the drift: neither `Taskfile.yml` nor `.github/workflows/ci.yml` runs a markdown link check, and a stale `#7-cross-references` link (pointing at "7. Fields") survived an earlier insertion unnoticed. After editing the section list, re-derive the anchors by listing `^## [0-9]+\.` and `\(#[0-9]+-` and reconciling the two.
- Apply when: adding, removing or reordering a numbered section in `docs/dsl-reference.md` (or any doc using `## <n>. Title` headings).

## Keyword surfaces fan out past the lexer, parser and tree-sitter grammar
- Type: pattern
- Learning: a new emod keyword touches several hand-maintained lists that no test cross-checks against `internal/lexer/token.go`: the TextMate alternation at `editors/vscode/syntaxes/emod.tmLanguage.json:63`, `keywordDescriptions` in `internal/lsp/hover.go:13`, and the per-context lists in `internal/lsp/completer.go`. `isKeyword` (`internal/lsp/hover.go:37`) is an *ordinal range* — `k >= lexer.KeywordModel && k <= lexer.KeywordExternal` — so every `Kind` appended after `KeywordExternal` (`mode`, `tags`, `decides_on`, `where`, `and`, `or`, `not`, `tag`, `events`, `emod`) is silently invisible to hover no matter what the description map contains. Decide per keyword whether each surface should cover it; do not assume adding the token propagates.
- Apply when: adding a keyword to `internal/lexer/token.go`, or auditing why a valid keyword has no VS Code highlighting, hover text or completion.

## Never write emod source with `%q` — the language has no escape sequences
- Type: constraint
- Learning: an emod string literal runs verbatim from one quote to the next; the lexer performs no unescaping. `%q`/`strconv.Quote` therefore breaks formatter idempotence — a backslash or tab in the text is written as two characters that read back as themselves, so `C:\hotel` becomes `C:\\hotel` then `C:\\\\hotel` on successive `emod fmt` runs. `formatter.go` has `quoted(text)` (`internal/formatter/formatter.go:47`) for this; every name and every description goes through it. The counterpart obligation is a round-trip subtest per hazard character (backslash, tab, quote, `%`, non-ASCII) asserting a second `Format` of the output produces identical bytes — `internal/formatter/formatter_test.go` has that table, and note the JSON/CUE exporters do the opposite (they must escape, and have their own export-then-decode subtests pinning that the text survives).
- Apply when: emitting emod source text from Go — the formatter, any codegen, LSP edits, or example generation.

## Additive output changes owe a byte-identical receipt for models that do not use the feature
- Type: convention
- Learning: every writer in this repo (`internal/formatter`, `internal/export`, `internal/diagram/drawio.go`, `internal/diagram/svg.go`) is expected to produce the exact bytes it produced before when the new field is absent, and the change must prove it rather than assert it. The diagram packages do this with `withoutDescriptions` (`internal/diagram/contract_test.go:589`), which strips the new prose from a model and compares shapes, fills, positions and arrows against the described render, so a change that added, moved or repainted a box fails. The undescribed `test.HotelReservation` fixture exists to be the same witness for the parser and CLI layers. State the receipt in the commit message; a reviewer reads its absence as unverified scope creep.
- Apply when: adding a field to any AST node that a formatter, exporter or diagram renderer writes out.

## A new exported field must land in JSON, CUE and `schema.cue` in the same change
- Type: constraint
- Learning: two subtests couple the three surfaces. "CUE and JSON exports describe the same model" (`internal/export/export_test.go:3317`) decodes both exports of one fixture and `require.Equal`s the documents, so teaching one format about a field fails immediately; "output conforms to the schema's Model definition" runs `cue vet -d '#Model'` against `internal/cue/schema.cue`, so the embedded schema must gain the field too. The diagram JSON document is deliberately *not* coupled: `jsonDiagramEvent` (`internal/export/export.go`) forks `jsonEvent` precisely so a new AST field cannot leak through a translation's inline event into the node-and-edge contract, and a subtest walks the whole diagram document asserting the key appears nowhere. Do not re-merge those two structs.
- Apply when: adding a field to the JSON or CUE export, or wondering why the diagram document has its own event type.

## The tree-sitter grammar must never be stricter than the Go parser
- Type: constraint
- Learning: `editors/tree-sitter-emod/grammar.js` is a deliberately looser mirror — a grammar stricter than the language red-squiggles files `emod validate` accepts, which is the one failure direction that matters. Every block body in `internal/parser/parser.go` is an unbounded `for !p.check(lexer.CloseBrace)` loop with no arity restriction, so `command X { fields {…} fields {…} }` is valid emod (verified: `go run ./cmd/emod validate` exits 0). Constructs therefore use `buildDescribedBlock($, …)` — `'{' repeat(choice($.description, ...items)) '}'` — and an `optional($.rule)` in a block body is a bug, not a constraint. Re-imposing at-most-one would also need an ambiguous `repeat($.description) optional(...) repeat($.description)`.
- Apply when: editing `grammar.js`, or reviewing a grammar diff that appears to "widen" a rule from `optional` to `repeat`.

## Shared fixtures come in an unfeatured/featured pair, guarded by a walk that must be extended
- Type: pattern
- Learning: `internal/test/fixtures.go` holds `HotelReservation` (uses no optional feature, witnesses that plain files still parse and still render byte-identically) alongside `DescribedHotelReservation` (exercises the feature everywhere it can appear, and is the one model the formatter, export and diagram packages assert against). Keep both roles when adding the next optional feature. The guard subtest "the shared described model describes every construct that accepts one" (`internal/parser/parser_test.go:3157`) only guards what `describableConstructs` (`:4050`) actually visits — the model, its actors, then every context and the slices below it — and what its `require.Subset` list names. A construct that gains the field but is not added to both is silently unguarded: dropping its description leaves the test green while the downstream round-trip tests quietly lose that input. Verify an extension by deleting the description from the fixture and confirming the test fails.
- Apply when: adding to or editing `internal/test/fixtures.go`, or extending an optional field to a new construct.

## De-duplicate before a fan-out edit, and land the de-duplication with proof
- Type: convention
- Learning: when the same edit would be copied into N sibling writers, this repo extracts the shape first: `writeCUEList`/`lineIfSet` replaced twelve `write*List` methods, `sliceXPositions`/`contextBounds`/`layoutWidth` replaced four copies of the layout arithmetic, `svgRectAttributes`/`svgRectElement` replaced three rect builders, `blankLineBetweenBlocks` replaced the `needsBlank`/index pairs, and `buildDescribedBlock` replaced nine brace-repeat-choice spellings. The extraction is welcome; what gets flagged is shipping ~300 mechanical lines inside a field-addition commit with nothing showing the output did not move. Carry a differential receipt (randomized-model diff, or the fixture across every format) and prefer a separate preparatory commit when the refactor is larger than the feature edit. Also give extracted helpers the parameters their siblings take — a `write*` helper that hardcodes indent level 0 while every sibling takes `level` invites a nested call that silently emits at column 0.
- Apply when: an edit would otherwise be pasted into more than about three sibling functions.

## A new block entry keyword owes three things to the parser's diagnostics
- Type: pattern
- Learning: (1) every construct's `default:`/`else` branch spells out the entries it accepts — eight messages read `expected description, … in <construct>` — so a new entry means editing all of them, and the tests assert that text. (2) A keyword whose value is malformed must report once: recover by draining the rest of the line with `p.checkSameLineAs(keywordTok)` and stopping at `lexer.CloseBrace` (see `parseDescriptionInto`, `internal/parser/parser.go:1288`), not with a single `p.advance()` — one unquoted description otherwise emits five diagnostics as each remaining word fails to match a block entry. (3) Pin it with `require.Len(t, diags, 1)`; that assertion appears throughout `internal/parser/parser_test.go` and is what makes the cascade a test failure.
- Apply when: adding a keyword that may appear inside a block construct in `internal/parser/parser.go`.

## Ask the lexer which keywords exist; never restate the set and never range over `Kind`
- Type: convention
- Learning: `internal/lexer/token.go` exports `Keywords() []string` (the thirty spellings, sorted, from the `keywords` map) and `Kind.IsKeyword()` (a lookup in the `keywordNames` inversion). Every keyword-coverage test iterates `lexer.Keywords()` — `internal/lexer/tokenizer_test.go:14`, `internal/parser/parser_test.go:225` and `:243`, `internal/oracle/oracle_test.go:44` — so a keyword added to the map is covered on the day the lexer learns it. The two failure modes this replaced both went unnoticed for a long time: a hand-written list drifts (the tokenizer's named twenty-one of thirty, silently omitting `mode`, `tags`, `decides_on`, `where`, `and`, `or`, `not`, `tag`, `events`), and an ordinal range over the iota block silently excludes everything declared past its bound (`checkIdentifierLike` was `typ < lexer.Identifier`; `isKeyword` in `internal/lsp/hover.go:37` is still `k >= lexer.KeywordModel && k <= lexer.KeywordExternal` and should be `k.IsKeyword()`).
- Apply when: writing any code or test that must treat "every keyword" uniformly, or adding a keyword to `internal/lexer/token.go`.

## A line-oriented declaration must gate every optional trailing token on the first token's line
- Type: constraint
- Learning: block bodies in `internal/parser/parser.go` loop until `}` or EOF, so nothing but an explicit line check stops a declaration from reaching into the next line. `parseField` read name, then type, then an optional modifier guarded only by identifier-likeness, and a modifier-less field therefore ate the following line's name — `roomType string` above `guestId string required` parsed as one field `roomType string guestId` plus a bogus `string required`. The guard is `p.checkIdentifierLikeSameLineAs(nameTok)` (`checkSameLineAs` + `checkIdentifierLike`), positioned against the *first* token of the declaration, and the failure path drains with the shared `p.skipRestOfLine(tok)` — which also stops at `lexer.CloseBrace`, so `fields { guestId }` still closes its block. Formatter idempotence does not catch this class: `emod fmt` rewrote the file into the mangled shape and was then byte-stable on the wreckage. Only a parse→format→reparse comparison against the original model does (`internal/formatter/formatter_test.go:427` "round-trip through the parser").
- Apply when: adding or editing a construct in `internal/parser/parser.go` whose parts sit on one line with any part optional.

## Exercise an omitted optional part mid-block, never as the last entry
- Type: pattern
- Learning: an optional part left out at the end of a block has nothing to run into, so it witnesses nothing. Every field in `HotelReservation`, `DescribedHotelReservation` and every `.emod` under `examples/` carries a modifier, which is why a `parseField` that could swallow the next line survived every round-trip, alignment and golden test in the repo. `KeywordFieldSearchCatalog` (`internal/test/fixtures.go`) deliberately puts its modifier-less fields mid-block ahead of a further field, and that placement is the whole point of the fixture — a reviewer should read a moved-to-the-end instance as coverage lost.
- Apply when: writing a fixture, corpus case or golden that is meant to cover an optional element being absent.

## A differential receipt must first prove the twin actually differs
- Type: convention
- Learning: the strip-or-rename helper behind a differential ("the two renderings are identical apart from X") is itself untested, and one that quietly misses a nesting level — e.g. the event nested inside a `translation`, which `test.WithOrdinaryFieldNames` has to walk explicitly — turns the receipt vacuous: identical inputs trivially produce identical output. Both differentials added for keyword-named fields open with `require.NotEqual` on the part that must move (`internal/export/export_test.go:2832`, `internal/diagram/contract_test.go:203`) before asserting everything else is equal. Pair every `withoutX`/`withOrdinaryX` comparison with that guard.
- Apply when: writing a test that compares a model against a transformed twin to prove a change reached exactly one surface.

## Name an extracted helper after the contract its callers rely on
- Type: recurring-finding
- Learning: two advisories in one story landed on the same defect — a helper whose name describes the happy path while callers depend on something else it does. `skipRestOfLine` (`internal/parser/parser.go`) also halts at `lexer.CloseBrace`, which is exactly what lets `fields { guestId }` close its block, so the name understates the stop condition (`skipRestOfLineOrBlockEnd` states it). `test.WithOrdinaryFieldNames` (`internal/test/fixtures.go`) uses the Go `With…` prefix, which promises a modified copy, but renames in place and returns the same pointer, so a caller keeping a reference to the original silently loses the keyword names (`RenameFieldsToOrdinary`, or a deep copy, removes the trap). Before naming an extraction, state the postcondition a second caller would rely on, then check the name says it.
- Apply when: extracting a shared helper from duplicated code, or adding an exported helper to `internal/test`.

## Put a new parser subtest in the group that owns the construct
- Type: convention
- Learning: `internal/parser/parser_test.go` is one umbrella split into thirteen top-level `t.Run` groups named for the area under test — "version header" (:23), "model and actors" (:322), "contexts, aggregates and slices" (:568), "commands, events and flows" (:764), "triggers" (:987), "views" (:1124), "automations" (:1392), "translations" (:1622), "error reporting" (:1849), "event sources and tags" (:2251), "descriptions" (:2587), "comments" (:3295), "decides_on" (:3491). A subtest belongs to the group that owns the construct it exercises, not to whichever group happened to hold the nearest prior example: the keyword-as-field-name subtests sit in "version header" (:225, :243) because a lone `emod`-named-field case lived there, though field parsing belongs under "commands, events and flows" and construct-name rejection under "error reporting".
- Apply when: adding a subtest to `internal/parser/parser_test.go` (or any of this repo's large umbrella test files).

## urfave/cli v2 discards every flag written after the file argument
- Type: constraint
- Learning: the app (`github.com/urfave/cli/v2 v2.27.7`, `internal/cli/app.go`) sets neither `SkipFlagParsing` nor any reordering, so parsing stops at the first positional argument and `c.String("format")` returns the flag's default however the user spelled the rest. Verified: `emod export examples/all_patterns.emod -f cue` prints JSON and exits 0, and `emod diagram examples/all_patterns.emod -f mermaid -o <path>` ignores both flags and writes `examples/all_patterns.drawio`. The README documents six invocations in exactly that shape (`README.md:117-127`). Only `glossary` honours it, by re-scanning the leftovers in `glossaryPathAndFormat` (`internal/cli/glossary.go`) for `-f`/`--format` in all four spellings; `validate`, `lint`, `export`, `diagram` and `slices` still read `c.Args().First()` and the parsed flag only. A story or acceptance criterion written as `emod <cmd> <file> -f <format>` therefore silently exercises the default format unless the command recovers the leftovers, and an end-to-end test that asserts only "exit 0" passes while proving nothing.
- Apply when: adding a flag or a command to `internal/cli/app.go`, writing an acceptance criterion or README example that puts a flag after the file, or debugging a format flag that appears to be ignored.

## New file-taking CLI commands compose `parseModelFile` and `reportExitError`
- Type: convention
- Learning: `parseModelFile(command, path)` (`internal/cli/parse.go`) is the shared read → `lexer.Scan` → `parser.Parse` → `formatText(diagnostics)` opening, and it produces the missing-file `LintError` — message `"<command> requires exactly one file argument"`, `ExitCode: 1`, `Cause: ErrMissingFileArgument` — that CLI tests branch on with `errors.As`. `validate.go:25`, `export.go:33`, `lint.go:117` and `diagram.go:35` each still hand-roll that same pair; `slices` and `glossary` call the helper. On the app side every `Action` is one line, `return reportExitError(RunX(...))` (`internal/cli/app.go:12`), which unwraps `*LintError` onto `urfave.Exit("", code)` and prints the message to stderr. Compose both rather than copying an older command's body, or the new command drifts on the cause callers match and on how diagnostics reach stderr.
- Apply when: adding a command to `internal/cli` that takes an `.emod` file.

## AST-to-bytes renderers are named `Export<Format>`
- Type: convention
- Learning: every renderer that turns a model into bytes takes the `Export<Format>(model *ast.Model) ([]byte, error)` form — `diagram.ExportMermaid`, `ExportASCII`, `ExportDrawio`, `ExportSVG` (the diagram four take a trailing `Style`), `export.ExportJSON`, `export.ExportCUE`, `export.ExportDiagramJSON`. `internal/glossary` is the single deviation (`RenderMarkdown`, `RenderJSON`), which a reviewer flagged; it stands as written. A third verb (`Write…`, `Generate…`, `Print…`) fragments the family further, so a new renderer package takes `Export<Format>` and a new format inside `internal/glossary` matches its in-package siblings.
- Apply when: adding an output format anywhere in the repo, or naming a new package's entry point.

## An assertion whose expected value comes from the code under test is the recurring review finding
- Type: recurring-finding
- Learning: three stories running, the reviewer's surviving advisory has been an assertion that cannot fail — a CLI diagnostic test asserting only position and count, a differential comparing a twin that was never proved to differ, and now `require.Equal(t, string(rendered), string(again))` in `internal/glossary/glossary_test.go` deriving its expected value from a second call to the renderer. A repeat-call assertion only has teeth where the path ranges over a Go map: `internal/glossary` never does (`actorDescriptions` and the `seen`/`referenced` maps are lookup-only), `internal/diagram/mermaid.go:158` sorts its tag keys precisely because it does. Before writing an assertion, name an input that makes it fail; if the only such input needs the implementation changed, it is filler — and filler bolted onto a subtest named for something else (declaration order, here) also gives that subtest a second reason to fail.
- Apply when: adding a "render/format it twice" or "compare against a re-derived value" assertion, or reviewing a subtest that asserts more than the behaviour its name states.

## `internal/glossary` collects once and renders twice; the collected document is the JSON shape
- Type: pattern
- Learning: `newDocument(model)` (`internal/glossary/glossary.go`) is the only walk of the AST — `RenderMarkdown` (`markdown.go`) and `RenderJSON` (`json.go`) both start from it — and `document`/`contextSection`/`term` carry the JSON tags directly, so there is no second serialized type to keep in step. Markdown-only concerns live in `markdown.go`: `termGroup`, the heading constants and the heading levels. Two rules the shape encodes: `description` deliberately takes no `omitempty` while every collection does, because an undescribed construct must arrive with an empty string (the JSON counterpart of the heading markdown keeps) — this is the opposite of `internal/export`, whose documents `omitempty` their descriptions, so its structs are the wrong thing to copy here; and a new term kind (US-005's invariants, say) is a field on `contextSection` plus one more `termGroup` passed to `appendGroups`, not a new traversal. `slice`, `trigger`, `automation` and `translation` contribute no term of their own — a `translation`'s nested event is listed among the events — and `docs/dsl-reference.md` section 10 states that.
- Apply when: adding a term kind, an output format, or a field to the glossary, or wiring a new JSON document elsewhere in the repo.

## A second `require.Contains` on one message is often shadowed by the first
- Type: recurring-finding
- Learning: asserting that a diagnostic names both a symbol and its scope with two `require.Contains` calls silently collapses when the scope name is a substring of the symbol — `require.Contains(t, diags[0].Message, "Loan")` at `internal/validator/validator_test.go:1247` cannot fail, because `"OneCopyPerLoan"` asserted on the line above already contains `Loan`, and mutating the message to drop the scope entirely leaves the subtest green. Assert the qualified fragment the message actually spells (`aggregate "Loan"`), or follow the group's own sibling at `:1408` and `require.Equal` the whole formatted line (`shelf.emod:12: invariant "Zulu" is already declared in aggregate "Loan"`), which is the shape the ordering subtests use. Before adding a `Contains` to a message that already has one, check the new needle is not inside the old one.
- Apply when: writing or reviewing a test that asserts a diagnostic message names more than one thing (symbol plus scope, rule plus name, type plus field).

## `emod fmt` canonicalises order, so a fmt golden is never the input re-indented
- Type: constraint
- Learning: `formatter.writeSlice` (`internal/formatter/formatter.go:145`) emits a slice's entries in a fixed kind order — description, trigger, commands, events, views, automations, translations, flows, specs last — and `writeContext`/`writeAggregate` hoist every `invariant` to just after `description`, above the first nested block. The AST stores each kind in its own slice, so source interleaving is unrecoverable and formatting moves declarations: none of `test.HotelReservation`, `test.KeywordFieldSearchCatalog` or `test.InvariantLibraryLending` is byte-stable under `Format` (verified — flows migrate past translations, field columns re-align). The consequence for `internal/cli/fmt_test.go`: pin a canonical `<name>FormattedEmod` constant (`:118`, `:135`) and pass *that* to `requireFmtSettlesOn` (`:381`). Passing `readFile(t, path)` back as the expected value, or `require.Contains`-ing lines that appear verbatim in the input fixture, leaves a subtest that also passes when `RunFmt` writes the file back unchanged — flagged twice by independent reviewers on one task (`:323`).
- Apply when: adding a subtest to `internal/cli/fmt_test.go`, writing a formatter golden, or choosing an input fixture for a formatting test.

## JSON and CUE order their document keys differently — do not mirror one struct into the other
- Type: convention
- Learning: in `internal/export/export.go` every `json*` document type opens with `Name`, then `Description`, then the positions, then `Comments`, then its children; the CUE side (`cueWriter.write*`, `internal/cue/schema.cue`) opens with `comments?` and then `name`. `jsonInvariant` (`export.go:66`) shipped with `Comments` ahead of `Name`/`Statement` — the CUE order transplanted into the Go struct — so the emitted invariant object reads with its keys in a different order from every sibling. Nothing catches this: the "CUE and JSON exports describe the same model" subtest decodes both into Go values before comparing, and key order does not survive decoding. Copy the ordering from a `json*` sibling, not from the schema.
- Apply when: adding a document type or field to `internal/export/export.go` or `internal/cue/schema.cue`.

## A new shared fixture owes `internal/oracle` a zero-diagnostic subtest

- Learning: US-011 Task 5 could not close by the letter. Its criterion listed the prose files a retired spelling may still appear in and added "any hit in a `.go`, `.js` or grammar-corpus file means US-004 is incomplete" — but the retirement's own negative tests must spell the retired form verbatim: `internal/parser/parser_test.go` (six inline sources across the kinded-trigger rejection subtests), `internal/cli/validate_test.go:100` "returns error naming retired trigger kind replacement", and `editors/tree-sitter-emod/test/corpus/slice.txt` "Slice with trigger kind rejected".
